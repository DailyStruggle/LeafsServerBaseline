# ADR-005: Retire Iris in Favor of Vanilla Datapack Worldgen

**Status:** Accepted
**Date:** 2026-06-08
**Author:** Leaf

---

## Context

The server's custom overworld was generated by the Iris Dimension Engine (Paper plugin). Over time the Iris investment grew large (hundreds of biome files, custom generators, jigsaw pools/structures, `.iob` objects, and a deploy/layering pipeline), but a re-examination showed the cost/benefit had shifted:

1. **Most biome files were Iris overhead, not content.** Of the ~240 `pack-overlay` biome files, the large majority were vanilla variants or fixes that existed only to patch Iris generation. The genuinely bespoke biomes number fewer than a dozen (the concept-hook biomes catalogued in `CUSTOM-BIOMES.md`: wildflower highlands, jacaranda forest, sea-glass shore, birch wetland, frosted rainbow forest, and the volcanic set).
2. **Key Iris features never worked reliably.** The `lava-spread` jigsaw pool and `frostpeak` lava behavior never functioned; biome-sampling NPEs and the v4 `jigsawStructures` migration gap were recurring maintenance costs.
3. **Vanilla datapack worldgen is more capable for what we actually want:**
   - **Biome-specific structures** are native and enforced via `worldgen/structure` `biomes` gating (inline lists or biome tags), which Iris did not honor reliably.
   - **Jigsaw** is the original, complete, battle-tested implementation (villages, bastions, ancient cities) with full `template_pool`, `processor_list`, `pool_aliases`, `terrain_adaptation`, `liquid_settings`, and `dimension_padding` support - a superset of Iris's partial clone.
   - **Tree/land scale variants** are cheap composition: feature size tiers + `placed_feature` density modifiers (`count`/`rarity_filter`/`noise_based_count`) for trees, and `multi_noise` parameter bands (erosion/weirdness) for terrain scale.
   - **Vanilla client compatibility** is free (no `derivative`/`vanillaDerivative` mapping discipline needed).
4. **Our tree generator is reusable.** `tree-gen` already builds a block list and full NBT-tag machinery (it emits Iris `.iob` and Sponge `.schem`). It can gain a vanilla structure-template `.nbt` writer to feed vanilla tree features and jigsaw pieces directly.

## Decision

1. **Retire the Iris world-gen pack.** It is no longer the active generation system. The Iris pack content is moved into a reserved archive at `legacy/iris/` (pack-base, pack-overlay, backups, generators, jigsaw assets, `.iob` output, object sources, deploy scripts, and the git-ignored `thirdparty-derived/` quarantine). It is retained for reference and asset salvage, not active deployment.
2. **Adopt vanilla datapack worldgen** as the generation system: custom biomes under `worldgen/biome`, terrain via `noise_settings` + density functions, climate placement via `multi_noise`, structures via `worldgen/structure` + `structure_set` + `template_pool`, and vegetation via `configured_feature`/`placed_feature`.
3. **Keep and repurpose the tree generator** as an active tool, relocated to `tools/tree-gen/`. It will gain a vanilla structure-template `.nbt` output mode (and `--format nbt` flag) so generated trees can be placed as vanilla features or jigsaw pieces.
4. **Re-author only the ~12 bespoke biomes**; drop the vanilla-variant/Iris-fix biomes as Iris-only artifacts. Express tree/land scale variants as thin vanilla biome files using feature and `multi_noise` composition.

This decision supersedes the engine assumption in ADR-003 (which assumed Iris for terrain complexity and vanilla-client compatibility); ADR-003's biome *design goals* (distinct palette, recognizable silhouette, build-theme anchor, shareable concept) remain in force and now apply to vanilla-authored biomes.

## Consequences

- Positive: removes a third-party engine dependency and its version churn; gains reliable biome-gated structures and the complete vanilla jigsaw toolbox; collapses ~240 biome files to ~12 bespoke + a handful of thin variants; tree/land scale variants become cheap composition.
- Positive: in-game iteration via `/place template`, `/place jigsaw`, and datapack reload, without a custom engine in the loop.
- Negative / trade-offs: vanilla terrain control is global (per `multi_noise`/density functions) rather than per-biome bespoke, so localized terrain (e.g. volcanic cones) leans on structures/features rather than terrain noise; the ~12 bespoke biomes and the `.iob` -> `.nbt` tree/structure conversion require re-authoring effort.
- Migration notes: the Iris deploy scripts now under `legacy/iris/scripts` are historical and are not run; project guidelines and design docs that reference the old `iris/` paths describe the retired system and should be read as historical until updated.

## Alternatives Considered

- **Keep Iris** - rejected; the maintenance burden, unreliable jigsaw/lava features, and large overhead of variant/fix biomes outweighed its bespoke-terrain advantage given only ~12 truly custom biomes are wanted.
- **Hybrid (Iris + vanilla datapack side by side)** - rejected as added complexity; the analysis showed vanilla covers all required cases.
- **Delete the Iris content outright** - rejected; archiving under `legacy/iris/` preserves authored assets (objects, palettes, structure pieces) for salvage during re-authoring.
