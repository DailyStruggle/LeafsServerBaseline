# Vanilla biome content plan (trees + sizes + decorators)

Goal: make the `vanilla/*` Iris biomes read like their Minecraft counterparts. Iris owns
decoration, so we replicate vanilla "material sources" ourselves via:

- `objects` -> multi-block tree `.iob` schematics (generated by `build-vanilla-trees.py`).
- `decorators` -> single-block surface flora (flowers, grass, ferns, petals, lily pads), using
  the Iris decorator format already used by base biomes (e.g. `frozen/pine-plains.json`:
  `chance`, `variance.style`, `zoom`, `palette[{block,data}]`).

Density note: current tree `chance` values (0.005-0.08) generate far too sparse. Proposed
column "tree chance/density" raises wooded biomes substantially and adds grass/flower decorators
(which were entirely absent before -> that is why everything looked barren).

Notes / open decisions:
- Sizes above are a proposed bump from the current uniformly "small" generation. Tree-gen
  `SPECIES["h"]` ranges would be widened per the legend (or per-biome size buckets generated).
- Decorator densities use Iris `chance` per column with `variance.style: STATIC` + small `zoom`
  for clumping (mirrors `pine-plains.json`).
- Bamboo / sweet_berry_bush / melon may need single-block decorators or tiny `.iob`s; flagged.
